# Web 인증 경계

## 현재 상태

`web/`의 로그인 화면은 현재 UI 템플릿입니다. 제출 이벤트의 기본 동작만 막으며 다음 동작은 수행하지 않습니다.

- 인증 제공자 호출
- API 로그인 또는 토큰 발급
- 토큰 저장
- 세션 쿠키 생성
- 로그인 후 리다이렉트

`api/`는 외부 OAuth2/OIDC 제공자가 발급한 RS256 Bearer 토큰을 검증합니다. API는 자체적으로 사용자 비밀번호를 받아 토큰을 발급하지 않습니다.

## 구현 원칙

- 실제 Identity Provider를 선택하기 전에는 성공 로그인 동작을 만들지 않습니다.
- 프론트엔드에 데모 역할 헤더를 추가하지 않습니다.
- 토큰은 외부 제공자 계약이 확정된 뒤 안전한 세션 방식으로 전달합니다.
- 보호된 API 요청은 `Authorization: Bearer <token>`을 사용합니다.
- 인증 실패는 `401`, 권한 부족은 `403`으로 표시합니다.

## 필요한 결정

프론트 로그인 구현 전에 다음 값을 확정해야 합니다.

- OAuth2/OIDC 제공자: Auth0, Keycloak, Google 또는 Custom
- Authorization Code + PKCE 사용 여부
- callback URL
- API audience
- issuer와 JWKS URL
- 웹 세션 저장 방식
- 로그아웃 및 토큰 갱신 정책

## 검증 가능한 현재 경계

- 인증 정보가 없는 보호 API 요청은 `401`입니다.
- 개발/스테이징에서 명시적으로 허용된 경우에만 데모 역할 헤더를 사용할 수 있습니다.
- 프로덕션에서는 데모 역할이 비활성화됩니다.

## 다음 구현 조건

Identity Provider와 callback 계약이 확정되면 `web/`에 다음 순서로 추가합니다.

1. provider client 설정
2. callback 및 세션 처리
3. 보호된 API 요청용 서버 인증 전달
4. 로그인 성공·실패·로그아웃 브라우저 테스트

현재 `SDTPL_ADM/`은 테마 참고용이므로 인증 구현 대상이 아닙니다.
