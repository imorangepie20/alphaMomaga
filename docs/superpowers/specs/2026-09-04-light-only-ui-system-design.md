# 라이트 전용 UI 시스템 재정비 설계

## 배경

`web/`은 범용 관리자 템플릿을 기반으로 시작했다. 템플릿의 다크 모드, 시스템 테마
추적, 원시 HTML 폼, 페이지별 Tailwind 클래스가 부동산 관리 기능과 함께 남아 있다.
그 결과 라이트 테마를 요구하는 운영 화면에서도 브라우저 설정에 따라 짙은 화면이
나오고, 폼의 글자 굵기, 라벨과 컨트롤 간격, 선택 목록의 표면이 화면마다 달라졌다.

이 작업의 목적은 개별 화면의 증상을 수정하는 것이 아니라, 전체 관리자 UI가 일관된
라이트 전용 시스템을 사용하도록 구조를 재정비하는 것이다.

## 범위

- `web/src/app/`의 인증, 대시보드, 운영, 설정, 사용자 및 템플릿 데모 화면
- `web/src/components/`의 레이아웃, 공용 UI, 대시보드, 앱, 페이지 컴포넌트
- 라이트 전용 테마 토큰, 타이포그래피, 표면, 테두리, 포커스 상태
- 폼, 다이얼로그, 테이블, 카드, 메뉴, 사이드바의 공통 시각 규칙
- Cloudflare Tunnel 주소에서의 브라우저 검증

API 도메인 모델, Auth0 인증 계약, BFF 요청 경계, `property -> tenant -> contract ->
payment -> maintenance` 업무 규칙은 변경하지 않는다.

## 목표와 비목표

### 목표

- 운영체제, 브라우저 저장소, HMR 상태와 무관하게 항상 라이트 테마를 사용한다.
- 모든 폼 필드는 라벨, 도움말, 컨트롤, 오류 메시지의 동일한 수직 리듬을 사용한다.
- 페이지가 직접 원시 `select`와 임의의 입력 표면·높이·간격을 정의하지 않는다.
- 제목, 라벨, 본문, 표 헤더, 버튼의 굵기 역할을 구분한다.
- 데모 화면과 실제 운영 화면이 같은 공용 컴포넌트 및 토큰을 사용한다.

### 비목표

- 다크 테마 재도입
- API endpoint, 데이터 구조, 권한 정책, 업무 상태 전이의 변경
- 디자인과 무관한 템플릿 기능 제거 또는 대규모 페이지 기능 재작성

## 설계 결정

### 1. 라이트 전용 테마 계약

- 루트 HTML은 `light` 클래스를 명시한다.
- `next-themes`, `ThemeProvider`, `ThemeToggle`, 시스템 테마 추적을 사용하지 않는다.
- `globals.css`는 라이트 토큰만 활성 계약으로 유지한다. 다크 토큰과 `dark:` 변형은
  마이그레이션 기간에 남아 있어도 활성 경로가 없어야 하며, 전체 화면 정리 후 제거한다.
- `color-scheme: light`를 루트에 선언해 날짜 입력, 선택 목록, 스크롤바 등 네이티브
  컨트롤도 라이트 표면을 사용하도록 한다.

### 2. 토큰 계층

`globals.css`를 다음의 의미 토큰으로 정리한다.

| 계층 | 책임 | 예시 |
| --- | --- | --- |
| 기본 | 색상, 반경, 간격, 글자 크기 | `--background`, `--radius`, `--space-2` |
| 의미 | 화면 역할 | `--surface`, `--surface-muted`, `--text`, `--text-muted` |
| 컴포넌트 | 반복 UI 상태 | `--control-height`, `--control-border`, `--dialog-padding` |

페이지 컴포넌트에는 원시 색상값과 독자적인 입력 높이를 추가하지 않는다. 상태 색상은
성공, 주의, 위험 의미 토큰으로 제한한다.

### 3. 타이포그래피와 간격

| 역할 | 규칙 |
| --- | --- |
| 페이지 제목 | `text-2xl font-semibold` |
| 섹션 및 다이얼로그 제목 | `text-lg font-medium` |
| 필드 라벨 및 표 헤더 | `text-sm font-medium` |
| 본문, 입력값, 일반 버튼 | `text-sm font-normal` |
| 보조 설명 | `text-sm text-muted-foreground` |

- 간격은 4px 기반을 사용한다.
- `FormField` 내부는 라벨과 컨트롤 사이에 8px(`gap-2`)을 둔다.
- 필드와 필드 사이에는 16px(`gap-4`)을 둔다.
- 두 열 레이아웃은 열 사이 12px 또는 16px을 명시한다.
- 입력 및 선택 컨트롤의 기본 높이는 36px(`h-9`)으로 통일한다.

### 4. 공용 폼 경계

새 `FormField` 컴포넌트를 도입한다. 이 컴포넌트는 `Label`, 선택적 도움말,
컨트롤 영역, 선택적 오류를 수직으로 배치한다. 운영 화면과 데모 화면은 이를 통해
라벨 간격을 얻으며, 페이지에서 `Label`과 `Input`을 직접 조합하지 않는다.

`Input`, `Textarea`, `NativeSelect`, Base UI `Select`는 같은 높이, 배경, 테두리,
포커스 링, 비활성 상태를 공유한다. 원시 HTML `select`는 `NativeSelect`로 옮기고
`option`은 시스템 색상 대신 라이트 토큰과 호환되는 표면을 사용한다.

### 5. 다이얼로그와 작업 영역

- 다이얼로그 헤더, 본문, 푸터를 분리한다.
- 푸터는 본문과 과도한 대비를 만들지 않고 상단 테두리와 일정한 패딩으로만 구분한다.
- 기본 너비는 업무 폼에서 필요한 필드를 무리 없이 수용하도록 설정하며, 작은 화면에서는
  16px의 좌우 여백을 유지한다.
- 저장, 취소, 위험 작업 버튼의 우선순위는 공통 `Button` variant로만 표현한다.

### 6. 화면 마이그레이션

다음 순서로 공용 시스템을 사용하도록 전환한다.

1. 전역 토큰과 공용 UI: `globals.css`, `Button`, `Input`, `Textarea`, `Select`,
   `NativeSelect`, `Label`, `Dialog`, `Card`, `Table`
2. 운영 흐름: `properties`, `tenants`, `contracts`, `payments`, `maintenance`,
   `inspections`
3. 공용 셸: 사이드바, 헤더, breadcrumb, command palette, notifications
4. 대시보드와 관리자 화면: 역할, 사용자, 보고서, 설정, 인증
5. 템플릿 앱 및 컴포넌트 데모 화면

각 단계는 공용 컴포넌트 변경 후 해당 화면군만 마이그레이션하고, 이전 단계의 시각
회귀를 확인한 뒤 다음 단계로 진행한다.

## 검증 전략

- 토큰 및 라이트 전용 레이아웃: 단위 테스트로 `ThemeProvider`와 `ThemeToggle`의 부재,
  루트 라이트 클래스, `color-scheme: light`를 검증한다.
- 폼 규칙: `FormField` 렌더링 테스트로 라벨-컨트롤 간격과 오류 메시지 연결을 검증한다.
- 기능 회귀: Properties, Tenants, Contracts, Payments, Maintenance, Inspections의 기존
  mutation 및 lifecycle 테스트를 유지한다.
- 브라우저: `https://mnre.approid.team/`에서 라이트 모드, 작은 화면, 키보드 포커스,
  다이얼로그, 날짜 입력, 선택 목록을 확인한다.
- 자동화된 UI 확인이 어려운 네이티브 선택 목록은 Chrome과 Edge에서 수동 확인 결과를
  문서에 기록한다.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 공용 컴포넌트 변경이 템플릿 화면을 깨뜨림 | 화면군별 마이그레이션과 lint·브라우저 검증 |
| 기존 페이지의 독자 클래스가 토큰을 덮어씀 | 화면별 원시 컨트롤과 중복 스타일을 검색해 제거 |
| HMR이 이전 테마 클래스를 남김 | 루트 라이트 클래스를 명시하고 완전 새로고침으로 검증 |
| 폼 밀도 변경이 업무 화면을 과도하게 길게 만듦 | 필드 내부 8px, 필드 간 16px 규칙만 적용 |

## 완료 기준

- 모든 페이지가 라이트 전용으로 렌더링되며 테마 전환 UI가 없다.
- 모든 관리 폼이 `FormField`와 공용 컨트롤을 사용한다.
- 핵심 운영 흐름의 입력, 저장, 오류 표시는 기존과 동일하게 동작한다.
- 템플릿 데모와 운영 화면의 카드, 테이블, 다이얼로그, 컨트롤이 동일한 토큰을 쓴다.
- Cloudflare Tunnel 브라우저에서 선택 목록과 날짜 입력의 라이트 표면을 확인한다.
