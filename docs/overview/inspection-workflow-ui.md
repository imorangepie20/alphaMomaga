# 점검 일정 및 완료 처리

## 배경과 원인

2026-09-05 점검 화면은 일정과 집계만 표시하고 등록·수정·검토·완료 처리가 연결되지 않았다.
API 역시 상태와 완료일만 수정할 수 있어 일정 변경과 긴급도 조정이 불가능했다.

## 구현

- 자산, 점검 유형, 예정일, 상태, 긴급도로 점검을 등록한다. 등록 후 실제 완료일을 입력해 완료 처리한다.
- 기존 점검은 예정일·긴급도·상태를 변경하고, 대기·예정에서 검토로 이동할 수 있다.
- 완료 버튼은 확인 폼을 열며, 저장 시 실제 완료일을 전송한다. 예정일보다 일찍 끝낸 점검도
  허용하며 서울 기준 오늘 이하여야 한다. 완료를 해제하면 API에서 완료일을 제거한다.
- 자산과 점검 유형은 수정 폼에서 읽기 전용이다. 점검 결과·첨부파일·담당자 관리는 별도 확장 대상이다.
- 검색, 자산·상태·긴급도 필터와 기한 초과 표시를 제공한다. 완료 점검은 기한 초과와 긴급 미완료
  집계에서 제외한다. 상단 지표는 필터와 무관하게 전체 조회 자료를 기준으로 한다.
- 변경은 기존 인증 프록시와 `inspection:manage` 권한 검사를 사용한다. 저장 중 중복 전송과
  폼 닫기를 차단하고, 실패하면 폼을 유지한다.
- `getInspectionWorkspace`는 점검과 자산만 조회하며 오류 시 예시 데이터로 대체하지 않는다.

## API 변경

`UpdateInspectionInput`에 `scheduledDate`, `priority`를 추가하고 PostgreSQL·인메모리 경로에
같이 반영했다. 기존 DB 열을 사용하므로 마이그레이션은 없다. DB 수정은 기존 트랜잭션과 감사 기록을 유지한다.

완료일 검증이 UTC 날짜를 사용해 한국 오전에 당일 완료를 거부하던 문제를 서울 날짜 기준으로 수정했다.
실재하지 않는 날짜의 자동 보정도 차단하고 상태·긴급도 허용값을 검사한다.

## 검증

### 2026-09-05 조기 완료 기록 수정

- 원인: 예정일을 실제 완료일의 하한으로 사용해 정상적인 조기 점검 완료가 API와 폼에서 거부됐다.
- 변경: 양쪽 하한을 제거하고 미래·불가능한 완료일의 서버 검증은 유지했다. 완료일을 오늘로
  자동 입력하지 않는다. 날짜 상한은 폼 열기·날짜 입력 시 서울 날짜로 갱신하고 제출 시 다시 검사한다.
- 테스트 우선으로 기존 거부를 재현했다. 조기 완료, 미래 날짜 거부 및 오래 열린 페이지의
  서울 날짜 경계 회귀 검사 포함 API 222개·웹 186개 통과. API 빌드·린트(기존 경고 4개),
  웹 TypeScript·변경 파일 ESLint 통과. DB 스키마와 기존 기록은 변경하지 않는다.
- 실제 Cloudflare 로그인 세션에서 점검 등록창 열기·취소를 데스크톱과 모바일로 검사해
  2개 통과했다(변경 요청 0건). 실제 완료 저장 및 PostgreSQL 경로는 이번 검수에 포함하지 않았다.

- 웹 전체 테스트 75개, API 전체 단위 테스트 184개 통과.
- 웹 변경 파일 ESLint 및 웹·API 프로덕션 빌드 통과.
- 등록·완료일 전달·필터·조회 실패, 일정 및 긴급도 변경, 완료 해제, 서울 날짜 경계를 검증했다.
- API 감시 프로세스가 수정 후 재시작되었고 로컬 `GET /inspections`는 HTTP 200을 반환했다.
- 인증된 Cloudflare 브라우저 변경 흐름과 실제 PostgreSQL 수정 시나리오는 이번 작업에서 검증하지 않았다.
