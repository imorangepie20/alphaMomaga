# 점검 일정 및 완료 처리

## 배경과 원인

2026-09-05 점검 화면은 일정과 집계만 표시하고 등록·수정·검토·완료 처리가 연결되지 않았다.
API 역시 상태와 완료일만 수정할 수 있어 일정 변경과 긴급도 조정이 불가능했다.

## 구현

- 자산, 점검 유형, 예정일, 상태, 긴급도로 점검을 등록한다. 등록 후 실제 완료일을 입력해 완료 처리한다.
- 기존 점검은 예정일·긴급도·상태를 변경하고, 대기·예정에서 검토로 이동할 수 있다.
- 완료 버튼은 확인 폼을 열며, 저장 시 실제 완료일을 전송한다. 예정일보다 일찍 끝낸 점검도
  허용하며 서울 기준 오늘 이하여야 한다. 완료를 해제하면 API에서 완료일을 제거한다.
- 자산과 점검 유형은 수정 폼에서 읽기 전용이다. 완료 시 점검 결과를 기록한다.
  첨부파일·담당자·구조화된 체크리스트 관리는 별도 확장 대상이다.
- 검색, 자산·상태·긴급도 필터와 기한 초과 표시를 제공한다. 완료 점검은 기한 초과와 긴급 미완료
  집계에서 제외한다. 상단 지표는 필터와 무관하게 전체 조회 자료를 기준으로 한다.
- 변경은 기존 인증 프록시와 `inspection:manage` 권한 검사를 사용한다. 저장 중 중복 전송과
  폼 닫기를 차단하고, 실패하면 폼을 유지한다.
- `getInspectionWorkspace`는 점검과 자산만 조회하며 오류 시 예시 데이터로 대체하지 않는다.

## API 변경

`UpdateInspectionInput`에 `scheduledDate`, `priority`를 추가하고 PostgreSQL·인메모리 경로에
같이 반영했다. 기존 DB 열을 사용하므로 마이그레이션은 없다. DB 수정은 기존 트랜잭션과 감사 기록을 유지한다.

완료일 검증이 UTC 날짜를 사용해 한국 오전에 당일 완료를 거부하던 문제를 서울 날짜 기준으로 수정했다.
실재하지 않는 날짜의 자동 보정도 차단하고 상태·긴급도 허용값을 검사한다.

## 검증

### 점검 결과 기록

- 날짜와 상태만으로 확인 항목·발견 사항·후속 조치를 알 수 없었으므로 `result`를 추가했다.
  완료 폼에서 1~4,000자 결과를 요구하며 목록에서도 표시한다. 과거 결과 없는 완료는
  조회를 허용하고 `점검 결과 기록 없음`으로 표시한다. 수정해 완료 상태로 저장할 때는 결과가 필요하다.
- API 입력 검증은 PostgreSQL이 숫자를 문자열로 자동 변환하기 전에 수행한다.
  빈 결과·과도한 길이·문자열 아닌 결과를 거부한다. 재점검 전환은 현재 완료 증빙을
  비우고 이전 결과와 날짜를 같은 트랜잭션의 감사 기록에 보존한다.
- migration `0004_goofy_ozymandias.sql`은 nullable `inspections.result` 열만 추가한다.
  격리 DB 검사 후 개발 DB의 호스트·포트·DB 식별 확인과 사전 백업을 거쳐 적용했다.
  백업은 개발 컨테이너 `property-manager-postgres`의
  `/tmp/pre-inspection-result-20260905.dump`에 있으며 `pg_restore --list`로 읽기를 확인했다.
  외부 보관 백업은 아니며 운영 복구 체계가 완성됐다는 의미는 아니다. seed나 기존 데이터 수정은 없다.
- API 224개·웹 187개 단위 검사, 인메모리 통합 30개, 점검·유지보수 격리 PostgreSQL 2개,
  API 빌드·린트(기존 경고 4개), 웹 타입·변경 파일 ESLint 통과.
- 실제 Cloudflare에서 데스크톱·모바일 등록 및 완료 수정 폼 열기, 결과 필수/길이 제한,
  화면 내 배치·취소 검사 2개 통과(변경 요청 0건). 실제 브라우저 저장은 미검수다.
- 별도 코드 리뷰에서 수정이 필요한 결함은 발견되지 않았다. 완료 신규 생성의 최대 길이,
  저장 실패 시 입력 유지, 동시 수정의 결과 이력 검사를 보강했다.

### PostgreSQL 완료 이력 검증

- 점검 재개 시 현재 완료일은 제거되지만 변경 전 완료일이 감사 기록에 없었다.
  `InspectionsService.update`에서 대상 행을 트랜잭션의 `FOR UPDATE`로 읽어 잠그고,
  변경과 같은 트랜잭션에 `previousCompletion.completedAt`을 기록한다.
- 격리 PostgreSQL의 `inspection-postgres.e2e-spec.ts`로 누락을 먼저 재현했다.
  조기 완료 저장, 연결 재생성 후 조회, 완료일 누락·미래 날짜의 롤백, 재개 시 NULL 저장,
  감사 이벤트 수와 이전 완료일, 동시 완료 수정의 이력 연결을 검증했다.
- 점검·유지보수 PostgreSQL 검사 2개, API 단위 222개, 인메모리 통합 30개,
  빌드 및 린트(기존 경고 4개) 통과. DB 전용 테스트는 일반 통합 실행에서 3개 skip하며
  별도 DB 실행에서 검증한다. CI의 PostgreSQL 단계에도 점검 검사를 추가했다.
- 운영 DB는 사용하지 않았다. 새 임시 DB에 migration만 적용하고 테스트가 만든
  UUID 자산·점검·감사 기록만 정리했다. 실제 브라우저 완료 저장 검수는 별도로 남는다.

### 2026-09-05 조기 완료 기록 수정

- 원인: 예정일을 실제 완료일의 하한으로 사용해 정상적인 조기 점검 완료가 API와 폼에서 거부됐다.
- 변경: 양쪽 하한을 제거하고 미래·불가능한 완료일의 서버 검증은 유지했다. 완료일을 오늘로
  자동 입력하지 않는다. 날짜 상한은 폼 열기·날짜 입력 시 서울 날짜로 갱신하고 제출 시 다시 검사한다.
- 테스트 우선으로 기존 거부를 재현했다. 조기 완료, 미래 날짜 거부 및 오래 열린 페이지의
  서울 날짜 경계 회귀 검사 포함 API 222개·웹 186개 통과. API 빌드·린트(기존 경고 4개),
  웹 TypeScript·변경 파일 ESLint 통과. DB 스키마와 기존 기록은 변경하지 않는다.
- 실제 Cloudflare 로그인 세션에서 점검 등록창 열기·취소를 데스크톱과 모바일로 검사해
  2개 통과했다(변경 요청 0건). 실제 완료 저장 및 PostgreSQL 경로는 이번 검수에 포함하지 않았다.

- 웹 전체 테스트 75개, API 전체 단위 테스트 184개 통과.
- 웹 변경 파일 ESLint 및 웹·API 프로덕션 빌드 통과.
- 등록·완료일 전달·필터·조회 실패, 일정 및 긴급도 변경, 완료 해제, 서울 날짜 경계를 검증했다.
- API 감시 프로세스가 수정 후 재시작되었고 로컬 `GET /inspections`는 HTTP 200을 반환했다.
- 인증된 Cloudflare 브라우저 변경 흐름과 실제 PostgreSQL 수정 시나리오는 이번 작업에서 검증하지 않았다.
