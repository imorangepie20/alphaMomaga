# Phase 26: Payments PUT 검증 강화

## 목표
수납 정보 수정 시 잘못된 상태가 저장소에 남지 않도록 업데이트를 원자적으로 검증합니다.

## 변경 사항

- `PaymentsService.update()`는 빈 입력을 거부합니다.
- 메모리 저장소에서 기존 결제를 직접 수정하지 않고 후보 객체를 만든 뒤 `validatePayment()`를 실행합니다.
- 검증에 실패하면 기존 결제 상태가 그대로 유지됩니다.
- 데이터베이스 경로는 기존 트랜잭션과 검증 흐름을 유지합니다.

## 검증 대상

- `Paid` 상태에는 `paidAt`이 필요합니다.
- 납부 예정일 전에는 `Overdue`로 변경할 수 없습니다.
- 납부일이 지난 결제는 `Pending`으로 변경할 수 없습니다.
- 결제 금액과 날짜 형식은 기존 검증 규칙을 따릅니다.

## 테스트

- 상태 및 납부일 업데이트
- 잘못된 상태 업데이트 후 기존 데이터 보존
- 빈 입력 거부
- 존재하지 않는 결제 거부

검증 결과: 18개 테스트 파일, 117개 테스트 통과 및 TypeScript 빌드 성공.
