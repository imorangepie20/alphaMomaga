# 자산 운영 현황 고도화

## 배경

기존 `/properties` 화면은 자산명, 위치, 유형, 점유율, 상태만 표시했다. 이 정보만으로는
관리자가 어느 자산의 수납, 계약, 유지보수, 점검을 먼저 처리해야 하는지 판단할 수 없었다.

## 원인

자산 목록이 `properties` 데이터만 조회하고 있었다. `property -> tenant -> contract ->
monthly_charge -> payment_receipt` 업무 흐름과 `maintenance`, `inspection`의 진행 상태가
자산 화면에 연결되지 않아 운영 위험이 화면에서 사라졌다.

## 변경 내용

- `/properties`는 해당 청구월의 자산, 임차인, 계약, 월별 청구, 유지보수, 점검을 병렬로 조회한다.
- `web/src/lib/property-operations.ts`는 자산별 활성 계약 수, 등록 임차인 수, 청구·수납·미수,
  90일 이내 계약 만료 수, 미완료 유지보수·점검 수를 계산한다.
- 상단 지표는 전체 자산, 평균 점유율, 이달 미수금, 조치 필요 자산 수를 표시한다.
- 목록 행은 기존 기본 정보와 함께 수납 및 운영 현황을 표시하며, 미수금·계약 만료·미완료 업무·검토
  상태가 있는 자산은 `확인 필요`로 표시한다.

## 데이터 해석 원칙

`properties` 모델에는 자산별 호실 총수 또는 가용 호실 정보가 없다. 따라서 임차인 수와 활성 계약 수는
표시하지만 공실 호실 수 또는 공실률을 추정하지 않는다. 이러한 값은 호실 재고 모델이 도입된 뒤에만
실제 값으로 제공한다.

## 검증

- `web/src/lib/property-operations.test.ts`에서 자산별 수납, 계약 만료, 미완료 업무 집계와
  공실 수를 임의 생성하지 않는 규칙을 검증한다.
- `npm.cmd run test -- property-operations.test.ts`
- `npm.cmd run build`
