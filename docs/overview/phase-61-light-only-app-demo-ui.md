# Phase 61: 앱 및 데모 라이트 UI 전환

## 변경 이유

공통 UI와 주요 운영 화면은 라이트 전용 계약으로 전환됐지만, 앱 데모와 컴포넌트
카탈로그에는 템플릿에서 가져온 `dark:` 변형이 남아 있었습니다. 이 상태에서는
라이트 전용 셸 안에서 색상 대비와 상태 표현이 화면마다 달라질 수 있습니다.

## 근본 원인

템플릿의 다크 모드 스타일이 개별 데모 컴포넌트에 직접 포함되어 있었고, 기존 회귀
검사가 대시보드와 오류 화면까지만 제한되어 앱·카탈로그·블록·템플릿·위젯 경로를
보호하지 못했습니다.

## 변경 내용

- Task 8의 고정 경로(`apps`, 컴포넌트 카탈로그, `blocks`, `templates`, `widgets`,
  `examples`)만 검사하는 라이트 UI 회귀 범위를 추가했습니다.
- 남아 있던 `dark:` 변형을 제거하고 기존 라이트 상태색과 의미 토큰을 유지했습니다.
- `components-field` 카탈로그의 사용자명 예제를 `FormField`로 전환해 공통 라벨,
  입력, 설명 간격 계약을 직접 보여 주도록 했습니다.
- 앱 데이터, drag-and-drop, 편집기, 캘린더, API와 인증 경계는 변경하지 않았습니다.

## 검증 결과

- RED: Task 8 회귀 테스트는 기존 `dark:` 변형과 `FormField` 미사용으로 실패했습니다.
- GREEN: `npm.cmd --prefix web run test -- src/app/globals.test.ts`에서 9개 테스트가
  통과했습니다.
- 정적 검사: Task 8의 고정 경로 검사에서 `dark:`, `ThemeProvider`, `ThemeToggle`이
  반환되지 않았습니다. 공통 `components/ui`의 잔여 다크 변형은 이 Task의 정확한
  변경 범위 밖이므로 후속 공통 UI 정비 범위로 남겼습니다.
- lint: Task 8 대상 ESLint는 오류 없이 완료됐습니다. 기존 데모의 경고 24개는 남아
  있으며 이번 변경으로 추가되지 않았습니다.
- 수동 브라우저 검증은 연결된 브라우저 세션이 없어 수행하지 못했습니다.
