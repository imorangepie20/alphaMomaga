# 회원가입과 권한 승인 대기

## 업무 기준

- 회원가입은 Auth0가 담당한다. 앱이 비밀번호를 수집하거나 가입 성공을 가장하지 않는다.
- 허용된 업무 역할 하나(Admin, PropertyManager, Finance, Inspector)가 토큰에 포함된
  상태를 승인으로 본다. 별도 승인 플래그와 역할이 불일치하는 이중 상태를 만들지 않는다.
- 관리자는 사용자 관리에서 업무에 맞는 역할을 부여한다. 관리자 역할을 기본 부여하지 않는다.
- 역할 부여 후 사용자는 대기 화면의 다시 로그인으로 새 토큰을 받아야 한다.
  승인 상태 다시 확인은 현재 세션의 토큰을 검사하며 강제로 새 권한을 발급하지 않는다.

## 구현 경계

- `/register`의 미동작 예제 폼을 제거하고 `/auth/login?screen_hint=signup`으로 연결했다.
  가입 후 `/pending-approval`로 돌아온다.
- `/auth/status`는 JWT 서명·issuer·audience·subject를 검증한 뒤 승인 상태만 반환한다.
  역할 없는 신원 허용 옵션은 이 상태 확인 경로에서만 사용한다.
  일반 업무 API의 AuthGuard는 기존처럼 역할 없는 토큰을 거부한다.
- 대시보드 layout은 승인 상태가 확인되어야 업무 UI를 렌더링한다.
  대기 화면은 로그인 필요, 승인되면 대시보드 이동, 미승인 시 안내와 로그아웃을 제공한다.
- API 장애, 만료 토큰, 잘못된 응답은 승인 대기로 단정하지 않고 확인 실패 안내를 표시한다.
  상태 조회는 서버에서 수행하고 캐시하지 않는다.
- 기존 토큰의 역할은 만료 전까지 유지될 수 있다. 즉시 권한 회수·차단 보장은
  별도 토큰 폐기/실시간 권한 확인 정책이 필요하며 이번 기능으로 해결됐다고 보지 않는다.

## 관리자 승인 처리

- 사이드바와 페이지 검색은 API가 확인한 역할의 권한으로 사용자·역할·보고서 항목을
  함께 필터링한다. 계정 설정은 유지한다. 권한 조회 실패 시 제한 메뉴를 숨기고 안내한다.
  이는 UI 안내이며 페이지와 API의 별도 권한 검사를 대체하지 않는다.
- 페이지 검색의 hydration 전 클릭 무반응을 실제 브라우저에서 재현해 공통
  `useHydrated`로 수정했다. 현재 비관리자 세션에서 직접 사용자 관리 접근 거부와
  사이드바·검색 내 사용자 관리 항목 미노출 검사 통과. 관리자 허용 분기는 단위 검사하며
  실제 관리자 브라우저 검수는 여전히 별도다.
- 사용자 목록에 로그인 가능 여부와 별도로 업무 승인 상태를 표시한다.
  허용 역할 없음은 승인 대기, 한 개는 역할 부여됨, 여러 개는 역할 검토 필요다.
  다른 앱의 역할은 이 앱의 승인으로 계산하지 않는다.
- 승인 필터는 Auth0에서 현재 읽은 페이지에만 적용한다. 전체 테넌트의 대기 수나
  전체 대기 목록으로 표시하지 않는다. 다른 페이지 또는 정확한 이메일 검색을 사용한다.
- 기존 운영 역할 선택·변경·테마 확인창으로 승인한다. 관리자·본인 보호는 유지한다.
  계정 차단 여부는 별도이므로 역할 부여만으로 차단 계정이 로그인 가능해지지 않는다.
- 웹 전체 183개 테스트 및 TypeScript·변경 파일 ESLint 통과.
- `e2e/admin-approval.spec.ts` 실제 실행은 저장된 세션의 사용자 관리 권한 부족으로
  실패했다. 접근 거부 화면을 확인했으며 권한을 우회하거나 운영 계정을 승격하지 않았다.
  실제 승인 필터 브라우저 검수는 `user:manage`가 있는 관리자 세션으로 실행해야 한다.

## 파비콘 파일

- 기존 프로젝트 로고를 16/32/48px PNG가 포함된 ICO로 변환했다.
  Next.js 파일 기반 `web/src/app/favicon.ico`를 교체한다.

  로고를 새로 생성하거나 외부 이미지로 대체하지 않는다.

## 검증 범위

- 추가 통합 검증: 로컬 JWKS 서버와 임시 RSA 키로 실제 RS256 JWT를 검증했다.
  미승인 토큰의 상태 조회 200, 자산·임차인·계약·수납·청구·유지보수·점검 조회 및
  유지보수 등록 차단, 승인 역할 토큰의 자산 접근 성공을 확인했다.
  위조 서명·만료·잘못된 issuer/audience는 상태 조회에서도 401이다.
  이전 미승인 토큰은 새 토큰 발급 뒤에도 미승인으로 남음을 확인했다.
  운영 Auth0·DB는 사용하지 않았으며 전체 인메모리 통합 검사 30개가 통과했다.
- 웹 전체 181개, API 전체 220개 및 추가 서명·subject 거부 테스트 통과.
  API 인메모리 통합 27개, API 빌드·린트, 웹 TypeScript·변경 파일 ESLint 통과.
  별도 읽기 전용 리뷰에서 구체적 보안·런타임 회귀는 발견되지 않았다.
- 승인/대기/서비스 오류 및 승인 후 대시보드 이동 단위 검사.
- 역할 없는 토큰은 승인 조회만 허용되고 기존 업무 토큰 검증에서는 거부됨을 검사.
- 실제 Cloudflare 브라우저에서 기존 승인 계정의 자산 화면 접근,
  회원가입 진입 링크와 3개 크기 ICO 응답 검사를 통과했다.
- 실제 미승인 Auth0 계정 생성과 관리자 역할 부여의 전체 실계정 검수는 아직 남아 있다.
  기존 계정의 역할을 제거하거나 테스트 계정을 운영 Auth0에 자동 생성하지 않았다.
