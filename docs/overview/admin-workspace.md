# 관리자 카테고리 실데이터 전환

## 원인

사용자는 고정 직원 목록, 보고서는 예시 지표, 설정은 가짜 프로필·구독 및 저장되지
않는 폼이었다. 역할 페이지는 API 실패를 고정 정책으로 숨기고 일부 권한명을 누락했다.

## 변경 범위

- 사용자: 현재 Auth0 세션 이름·이메일과 API `/auth/me`에서 검증한 역할·권한을 표시한다.
  전체 직원 목록으로 오인하지 않도록 현재 로그인 계정이라고 명시한다.
- 역할: 실제 `/admin/roles` 정책을 업무별 비교표로 제공한다. `property:manage`,
  `billing:manage`와 알려지지 않은 식별자도 누락하지 않는다. API 실패 시 대체 정책 없음.
- 보고서: `report:read` 확인 후 청구월별 확정 청구·배분 수납·미수 및 자산 명세를 표시한다.
  CSV는 동일 조회 스냅샷을 사용하며 UTF-8 BOM, 따옴표 escaping, 수식 입력 방어를 적용한다.
- 설정: 현재 계정, 서울 시간대·원화·한국어·라이트 테마·청구월 집계 기준을 표시한다.
  영속 저장 API가 없는 가짜 수정·저장·구독 결제 버튼은 제거했다.
- 사용자·역할 페이지는 `user:manage`, 보고서는 `report:read`를 서버에서 검사한다.
  세션 토큰은 서버에서만 사용하며 브라우저에 전달하지 않는다. 보고서 수납 조회는
  기존 청구 API의 추가 권한 검증도 그대로 통과해야 한다.

## 남은 기능과 경계

Auth0 Management API 연결과 직원 디렉터리 저장소가 없다. 따라서 전체 사용자 조회,
초대·차단·역할 할당을 앱 안에서 수행하는 기능은 아직 구현하지 않았다. 계정 변경은
Auth0 관리 콘솔에서 수행하고 재로그인하여 API 적용 역할을 확인해야 한다.
역할별 권한 편집은 서버 정책 변경이며 웹에서 수정 가능한 것처럼 표시하지 않는다.
설정 영속 저장 API도 없으므로 현재 적용값 확인 화면이다.

이 작업은 기존 업무 데이터나 실제 Auth0 계정·권한을 수정하지 않는다.
기존 템플릿 설정 컴포넌트는 다른 예제의 참조 가능성을 고려해 삭제하지 않고 연결만 제거했다.

## 검증

- 웹 전체 121개 테스트 통과: 관리자 권한 차단, 서버 토큰 사용, 역할 API 오류,
  월 선택·보고서 접근, 예시 사용자 제거, 권한표, CSV 수식 방어 포함.
- 변경 파일 ESLint 및 프로덕션 빌드 통과.
- 인증된 Cloudflare 브라우저 시각 검증과 실제 파일 다운로드 수동 검증은 미실행.
